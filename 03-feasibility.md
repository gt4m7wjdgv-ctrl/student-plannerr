# 03 - Feasibility Analysis

## 1. Technical Feasibility

The project is technically feasible. The proposed system can be developed using commonly available technologies:

- HTML, CSS, and JavaScript for the user interface.
- Python for application logic.
- SQLite for storing schedules and tasks.

These technologies are suitable for a small academic project and can be used with commonly available development tools.

Assessment: Technically feasible.

## 2. Economic Feasibility

The project can be developed with free or open-source tools. SQLite does not require a separate database server for this small system. Therefore, the expected development cost is low.

Possible costs may include development time and, if the system is later published online, hosting costs.

Assessment: Economically feasible for a student project.

## 3. Organizational Feasibility

The system supports a common student need: organizing academic activities. Its features are straightforward and should require little training. Students can enter their own classes, study plans, assignments, and exam dates.

Assessment: Organizationally feasible.

## 4. Risks

- Incorrect data entry: Provide clear input fields and validation.
- Missed reminders: The first version can display upcoming deadlines; automatic notifications may be considered later.
- Limited development time: Focus on essential features first.
- Data loss: Encourage users to keep a backup of important information.

## 5. Final Recommendation

Based on the technical, economic, and organizational analysis, the Student Planner and Management System is feasible as a student project.

It is recommended to proceed with planning and development, beginning with the core scheduling and task-management features.
